# tdd-new-edge-module

## 목적
CLAUDE.md의 "TDD 워크플로우"·"모킹 금지"·"혼자 개발 주도 금지" 규칙을 실제로 지키면서 새 엣지 모듈을 추가한다.

## 절차 (반드시 순서대로, 단계마다 개발자 확인 후 다음 단계로)

1. **요구사항 확인**: 이번에 추가할 기능이 개발계획서/기능명세서의 어느 항목(M2 zone 집계 / M3 로컬버퍼·업링크 등)에 해당하는지 먼저 확인하고 개발자와 범위 합의
2. **Red**: 실패하는 테스트부터 작성 — 실제 입력(예: 실제 프레임 배열, 실제 SQLite 파일)을 사용, mock으로 대체 금지
3. 테스트 실행 → 실패 확인 (여기서 코드가 없어서 나는 실패인지 확인하고 개발자에게 보고)
4. **Green**: 테스트를 통과시키는 최소 코드만 작성 — 요청받지 않은 기능(예: 아직 필요 없는 다중 zone 지원) 추가 금지
5. 테스트 재실행 → 통과 확인, 개발자에게 결과 공유
6. **Refactor**: 가독성/중복 제거/성능 최적화, 테스트는 계속 통과 상태 유지
7. 커버리지 확인 (목표 90% 이상) — 미달이면 어느 분기가 테스트 안 됐는지 짚어서 보고
8. 완료 후 CLAUDE.md에 추가할 만한 컨벤션/주의사항이 생겼는지 확인하고 제안 (CLAUDE.md "문서화 제안 의무")

## 하지 말 것
- 여러 단계를 한 번에 처리해서 "다 됐습니다" 식으로 한꺼번에 보고하지 않는다
- 테스트를 나중에 채워 넣겠다며 구현 코드부터 짜지 않는다
- 커버리지를 올리기 위해 의미 없는 테스트(assert True 등)를 추가하지 않는다
